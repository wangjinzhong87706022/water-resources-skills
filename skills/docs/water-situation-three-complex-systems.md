# water-situation 三大复杂系统详解

> **概述**：water-situation 的"高复杂度"主要来自三个相互独立的复杂系统：**多基准系统**、**多类型系统**、**阈值系统**。每个系统都有特定的业务规则、数据质量问题和使用约束。

---

## 一、多基准系统（Elevation Datum System）

### 1.1 什么是"多基准"？

**高程基准**（Elevation Datum）是测量水位的**零点参考系**。不同地区、不同历史时期可能使用不同的基准，就像"海平面"本身也有不同的定义（如吴淞口、废黄河口等）。

#### 通俗类比

想象你站在不同城市的地铁站：
- 北京地铁站海拔 **50米**（以黄海平均海平面为基准）
- 上海地铁站海拔 **4米**（以吴淞口为基准）
- 两者相差 46米，**不是真实的高差，而是基准不同**

水文水位测量也存在类似情况：同样的"13米水位"，在不同基准下代表的**实际水面高度完全不同**。

### 1.2 本库的三种基准

| 基准名称 | 实测数据 | 典型测站 | 使用区域 |
|---------|---------|---------|---------|
| **废黄河口** | 多数（具体数值未统计） | 宝应、高邮 | 里运河沿线（扬州） |
| **冻结(吴淞)** | 少数（1个） | 大通(二) | 长江流域 |
| **1985 国家高程基准** | **0 条**（未发现） | - | - |

#### 基准1：废黄河口

- **定义**：以废黄河（历史上黄河夺淮入海形成的废河道）入海口的某个固定点为高程零点
- **背景**：黄河历史上多次改道，在江苏留下"废黄河"河道
- **使用区域**：江苏省里下河地区（包括扬州里运河沿线）
- **特点**：
  - 与 1985 国家高程基准存在系统差（差值约 **0.19m**）
  - ⚠️ **本库无可比对站点验证此差值**
- **实测测站**：
  - 宝应（dtmel=0.000）
  - 高邮(大)（dtmel=0.000）
  - 洪泽湖蒋坝站（dtmel=NULL，**高程值缺失**）

#### 基准2：冻结(吴淞)

- **定义**：
  - **吴淞**：上海吴淞口验潮站历史平均海平面，是中国东部沿海经典高程基准之一
  - **冻结**：表示该站高程数据在某次统一校测后**锁定不再变动**，采用历史冻结值
- **使用区域**：长江流域（如大通站）
- **特点**：
  - 吴淞基准本身与 1985 国家高程基准也有系统差
  - "冻结"表示不随后续地面沉降/水准网更新而调整
- **实测测站**：
  - 长江大通(二)（dtmel=-1.860）

#### 基准3：1985 国家高程基准

- **定义**：中国现行法定高程基准，1987 年正式启用
- **本库实测**：**未发现任何测站使用此基准**
- **常见误解**：
  - ❌ "洪泽湖默认 1985 国家高程基准"
  - ❌ "sl323 库统一用 1985 基准"
  - ✅ **实际情况**：本库以"废黄河口"为主，存在"冻结(吴淞)"，**不能假设统一基准**

### 1.3 为什么"多基准"是问题？

#### 问题1：跨站对比时需要基准换算

**示例**：洪泽湖 vs 长江水位对比

```sql
-- 查询两个测站的水位和基准
SELECT r.tm, r.z, b.stnm, b.rvnm, b.dtmnm, b.dtmel
FROM st_river_r r
JOIN st_stbprp_b b ON r.stcd = b.stcd
WHERE b.stnm IN ('蒋坝', '大通(二)')
  AND r.tm >= '2024-01-01' AND r.tm < '2025-01-01'
```

**返回结果**：
```
蒋坝：水位 13.148m（基准：废黄河口，高程值 NULL）
大通(二)：水位 9.528m（基准：冻结(吴淞)，高程值 -1.860）
```

**数值差**：13.148 - 9.528 = **3.62m**

**问题**：
- ❌ 这 3.62m **不代表真实水位差**
- ✅ 包含了**基准系统偏差**（废黄河口 vs 吴淞）
- ✅ 真实水位差需减去基准差（约 0.19m），但**本库无可比对站点验证**

#### 问题2：基准信息缺失

**洪泽湖蒋坝站**：
```
dtmnm = '废黄河口'  （基准名称有值）
dtmel = NULL        （高程值缺失）
```

**这意味着**：
- ✅ 知道基准名称（废黄河口）
- ❌ 不知道高程值（NULL）
- ⚠️ 无法进行精确的基准换算

#### 问题3：不能硬编码基准差值

**常见错误**：
```python
# ❌ 硬编码基准换算
hongze_water_level = 13.148
elevation_diff = 0.19  # 废黄河口 vs 1985基准
real_level = hongze_water_level + elevation_diff
```

**问题**：
- 0.19m 是**常识**，但**本库无可比对站点验证**
- 洪泽湖蒋坝站 dtmel=NULL，无法验证此差值

### 1.4 使用规则

#### 规则1：查询阶段

默认返回数据库中原始值，**不自动换算基准**。

```sql
-- ✅ 正确：返回原始值和基准名称
SELECT r.tm, r.z, b.stnm, b.rvnm, b.dtmnm
FROM st_river_r r
JOIN st_stbprp_b b ON r.stcd = b.stcd
```

#### 规则2：输出阶段

**始终标注基准名称**：
```
洪泽湖年均水位 13.148m（基准：废黄河口）
长江年均水位 9.528m（基准：冻结(吴淞)）
```

**跨站对比时预警**：
```
⚠️ 两站基准不同（废黄河口 vs 冻结(吴淞)），
绝对水位不可直接对比，数值差包含系统偏差
```

#### 规则3：基准缺失处理

当 `dtmnm` 为空或 `dtmel` 为 NULL 时：
```
水位：13.148m（基准：废黄河口，高程值未记录）
```

- ❌ **不要猜测基准**（即使知道该区域通常用某基准）
- ✅ **说明缺失**："本站基准信息缺失，建议对接省防指档案确认"

### 1.5 数据质量实况

| 测站 | 水体 | dtmel | dtmnm | 数据状态 |
|------|------|-------|-------|---------|
| 蒋坝 | 洪泽湖 | NULL | 废黄河口 | ⚠️ 高程值缺失 |
| 大通(二) | 长江 | -1.860 | 冻结(吴淞) | ✅ 有值 |
| 宝应 | 里运河 | 0.000 | 废黄河口 | ✅ 有值 |
| 高邮(大) | 里运河 | 0.000 | 废黄河口 | ✅ 有值 |

**统计**：
- **1985 国家高程基准**：0 条（本库未发现）
- 高程值（dtmel）缺失：部分测站（如蒋坝）

## 二、多类型系统（Water Body Classification System）

### 2.1 什么是"多类型"？

数据库中 `rvnm`（河名字段）将**不同类型的自然水体**（河流、湖泊、运河）放在同一层级，**不区分水体类型**。系统需要根据业务规则**识别并标注**水体类型。

#### 通俗类比

想象一个表格，把所有"水域"都列在一起：
```
水域名称
--------
长江       ← 天然河流
洪泽湖     ← 湖泊
里运河     ← 人工运河
三阳河     ← 人工运河
```

如果直接按"河流"查询，会把湖泊、运河都混进来，造成**语义混淆**。

### 2.2 四级分类体系

| 类别 | 定义 | 示例 |
|------|------|------|
| **天然河流** | 自然形成、有流域面积 | 长江、淮河 |
| **湖泊** | 天然或半天然蓄水体 | 洪泽湖、高邮湖、宝应湖 |
| **人工运河** | 人工开凿的航运/输水河道 | 里运河、三阳河、潼河 |
| **水库** | 人工拦河筑坝形成的蓄水体 | 大型水库 |

### 2.3 扬州地区常见水体分类

| 名称 | 水体类型 | 业务分类 | 说明 |
|------|---------|---------|------|
| **长江** | 天然河流 | 干流 | 过境河流，江苏段长约 400km |
| **淮河** | 天然河流 | 干流 | 经扬州北部入江 |
| **洪泽湖** | **湖泊**（调蓄型） | 淡水湖 | 中国第四大淡水湖，**非天然河流** |
| **高邮湖** | 湖泊 | 淡水湖 | 与洪泽湖同属淮河流域 |
| **宝应湖** | 湖泊 | 淡水湖 | 位于宝应县 |
| **古运河** | 人工运河/天然河流 | 古运河 | 京杭大运河扬州段，部分为天然河道改造 |
| **里运河** | **人工运河** | 运河 | 苏北灌溉总渠段，人工开凿航运运河 |
| **新通扬运河** | 人工运河 | 运河 | 人工开挖，连接长江、淮河 |
| **三阳河** | 人工运河 | 运河 | 南水北调东线工程河道 |
| **潼河** | 人工运河 | 运河 | 南水北调东线工程河道 |

### 2.4 为什么"多类型"是问题？

#### 问题1：统计口径混乱

**用户提问**："2024年平均水位最高的前3条**河流**"

**数据库中 `rvnm` 不分类型**：
```
洪泽湖（湖泊）→ 会被当成"河流"
长江（天然河流）→ 确实是河流
里运河（人工运河）→ 会被当成"河流"
```

**❌ 错误写法**（容易误导）：
```
2024年平均水位最高的前3条河流依次为：
1. 洪泽湖（13.148m）   ← 湖泊被当成河流
2. 长江（9.528m）
3. 里运河（6.779m）    ← 人工运河被当成河流
```

**✅ 正确写法**（前置标注分类）：
```
2024年扬州辖区水域年均水位排名前三：

| 排名 | 名称 | 水体类型 | 年均水位 |
|------|------|---------|---------|
| 1 | 洪泽湖 | **湖泊**（调蓄型淡水湖） | 13.148m |
| 2 | 长江 | **天然河流**（干流） | 9.528m |
| 3 | 里运河 | **人工运河** | 6.779m |

⚠️ 若业务报表严格限定"天然河流"，应仅保留长江参与排名。
```

#### 问题2：统计意义不同

不同水体类型的**水位含义**不同：
- **天然河流**：过境水量，反映流域来水
- **湖泊**：调蓄水量，反映蓄水状态
- **人工运河**：输水/航运，反映调度状态
- **水库**：蓄水量，反映供水/防洪能力

**不能直接横向比较**不同类型的水位。

#### 问题3：判断逻辑复杂

**古运河 vs 里运河**：
- **古运河**：京杭大运河扬州段，部分为天然河道改造 → **人工运河/天然河流**（需结合具体河段）
- **里运河**：苏北段人工运河 → **人工运河**

**湖泊 vs 水库**：
- **湖泊**：天然或半天然，岸线固定（如洪泽湖）
- **水库**：人工筑坝形成，有"库水位"指标
- **数据库区分**：`st_river_r` 表存储湖泊水位，`st_rsvr_r` 表存储水库水位

### 2.5 使用规则

1. **查询阶段**：不改变查询逻辑，仍按 `rvnm` 分组
2. **输出阶段**：根据 `rvnm` 匹配知识库，**前置标注水体类型**
3. **分类争议时**：优先标注"类型待确认"而非猜测
4. **跨域对比**：注意不同水体类型的统计意义不同

## 三、阈值系统（Threshold System）

### 3.1 什么是"阈值"？

**阈值**是水利工程中的**关键控制指标**，用于判断水位是否"超警戒"或"超保证"，是防汛抗旱的核心依据。

#### 通俗类比

- **警戒水位（WRZ）**：洪水位达到这个值，需要**警惕**并准备应对
- **保证水位（GRZ）**：洪水位达到这个值，意味着**紧急状态**，需要全力抢险

类似于：
- 体温 37.5°C → **警惕**
- 体温 39°C → **紧急就医**

### 3.2 两类核心阈值

| 阈值类型 | 字段名 | 定义 | 触发响应 |
|---------|--------|------|---------|
| **警戒水位** | WRZ | 水位达到此值时需警惕 | 启动预警，加强巡查 |
| **保证水位** | GRZ | 水位达到此值需紧急处理 | 全力抢险，可能转移群众 |

### 3.3 数据质量：极差！⚠️

#### 实测统计（2026-07-13）

| 字段 | 总记录数 | 非空记录数 | 非空率 | 状态 |
|------|---------|-----------|-------|------|
| **WRZ（警戒水位）** | 231 | 176 | **76%** | ⚠️ 部分有值 |
| **GRZ（保证水位）** | 231 | **0** | **0%** | ❌ **全部为空** |
| WRQ（警戒流量） | 231 | 部分 | 待统计 | ⚠️ |
| GRQ（保证流量） | 231 | 部分 | 待统计 | ⚠️ |
| LDKEL/RDKEL（岸高程） | 231 | ~20 | ~9% | ❌ 基本为空 |

#### 关键发现

1. ❌ **GRZ（保证水位）全表 0% 有值** → **该字段完全不可用**
2. ⚠️ **WRZ（警戒水位）仅 76% 有值**，且主要集中在**闸泵站**
3. ❌ **水位站（ZZ）/水文站（ZQ）的阈值字段基本全部为空**

#### 三水域代表站实测

| 测站 | 水体 | WRZ | GRZ | 状态 |
|------|------|-----|-----|------|
| 蒋坝 | 洪泽湖 | **NULL** | **NULL** | ❌ 全部缺失 |
| 大通(二) | 长江 | **NULL** | **NULL** | ❌ 全部缺失 |
| 宝应 | 里运河 | **NULL** | **NULL** | ❌ 全部缺失 |

**结论**：三水域代表站的阈值数据**全部缺失**，数据库中**不存在**：
- "洪泽湖警戒水位 14.35m"
- "长江警戒水位"等数值

### 3.4 为什么"阈值系统"是问题？

#### 问题1：查询前必须验证（3步验证法）

**Step 1：验证表中有数据**

```sql
SELECT COUNT(*) as cnt
FROM sl323.st_rvfcch_b
WHERE STCD = '目标测站编码'
  AND (WRZ IS NOT NULL OR GRZ IS NOT NULL)
```

**判断逻辑**：
```python
if cnt == 0:
    return "⚠️ 该站阈值数据缺失，无法判断超警戒/超保证状态"
```

**Step 2：验证字段值非空**

```sql
SELECT STCD, WRZ, GRZ
FROM sl323.st_rvfcch_b
WHERE STCD = '目标测站编码'
```

```python
if row['WRZ'] is None:
    warn("⚠️ 警戒水位数据缺失（WRZ=NULL）")
if row['GRZ'] is None:
    warn("⚠️ 保证水位数据缺失（GRZ=NULL）")  # GRZ 全表都为空
```

**Step 3：验证数值合理性**

```python
if row['WRZ'] is not None:
    if not (0 < row['WRZ'] < 20):
        warn(f"⚠️ 警戒水位异常：{row['WRZ']}m（超出合理范围）")
```

#### 问题2：不能硬编码阈值

**❌ 错误做法**（来自案例）：
```python
# 硬编码洪泽湖警戒水位
hongze_wrz = 14.35  # 来自外部文件
```

**问题**：
- ❌ 无法证明此数值与数据库一致
- ❌ 数据源不透明
- ❌ 蒋坝站 WRZ=NULL，数据库根本无此数据

**✅ 正确做法**：
```python
# 先从数据库查询，验证存在后再使用
threshold = query_threshold('蒋坝站STCD')
if threshold['WRZ'] is None:
    return "⚠️ 蒋坝站警戒水位数据缺失，无法判断超警戒状态"
else:
    compare_with_threshold(current_z, threshold['WRZ'])
```

#### 问题3：缺失时的处理

**缺失时的用户告知模板**：
```markdown
⚠️ **阈值数据缺失说明**

- 测站：蒋坝（洪泽湖）
- 缺失字段：WRZ（警戒水位）= NULL，GRZ（保证水位）= NULL
- 数据来源：sl323.st_rvfcch_b
- 影响：无法判断当前水位是否超警戒/超保证

**建议**：
1. 对接省防指调度文件，获取洪泽湖最新防洪指标
2. 或使用历史同期水位作为参考（如近5年同期最高水位）
```

#### 问题4：历史极值替代方案

当阈值缺失时，可提供**历史极值**作为参考：

```sql
SELECT MAX(z) as historical_max,
       PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY z) as p99,
       COUNT(*) as n
FROM st_river_r r
JOIN st_stbprp_b b ON r.stcd = b.stcd
WHERE b.stnm LIKE '%蒋坝%'
  AND r.tm >= DATE_SUB(CURDATE(), INTERVAL 10 YEAR)
  AND r.z IS NOT NULL
```

**输出说明**：
```
📊 **历史水位参考**（蒋坝站，近10年）
- 历史最高水位：14.25m（2020-07-21）
- p99 水位：13.85m
- ⚠️ 此数据**非官方阈值**，仅供参考
```

### 3.5 数据质量差异

| 测站类型 | 有阈值记录比例 | 典型基准 |
|---------|--------------|---------|
| **闸泵站（HP 开头）** | **较高**（部分有值） | 废黄河口 |
| **水位站（ZZ）** | **极低**（基本为空） | 待确认 |
| **水文站（ZQ）** | **极低**（基本为空） | 待确认 |

**结论**：
- ✅ 闸泵站（HP 编码）的阈值数据相对完整
- ❌ 水位站（ZZ）和水文站（ZQ）的阈值字段**基本全部为空**
- ❌ **不要假设所有测站都有阈值数据**

### 3.6 数据缺失的根本原因

可能原因（待确认）：
1. **表结构设计问题**：`st_rvfcch_b` 中水位站/水文站的阈值字段未填充
2. **数据来源问题**：阈值数据可能存储在其他系统（如省防指调度系统）
3. **历史遗留**：该表可能主要服务于闸泵站，水位站数据未迁移

### 3.7 不能引用的外部数据

| 数值 | 来源 | 可用性 |
|------|------|--------|
| 14.35m | 案例引用 | ❌ **无法证实**（数据库无此数据） |
| 12.81m | 案例引用 | ❌ **无法证实** |
| 13.31m | 案例引用 | ❌ **无法证实** |
| 0.19m（基准换算） | 案例引用 | ⚠️ **常识但本库无实测支撑** |

**正确做法**：
> "本库中蒋坝站阈值数据缺失，无法引用 14.35m 等数值。如需防洪评估，建议对接省防指调度文件。"

## 四、三个系统的相互关系

```
┌─────────────────────────────────────────────────────────┐
│           water-situation 三大复杂系统                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌──────────────┐                                       │
│  │ 多基准系统   │ ← 决定水位值的"零点"参考               │
│  │ (3种基准)    │   废黄河口 / 冻结(吴淞) / 1985基准     │
│  └──────┬───────┘                                       │
│         ↓                                               │
│  ┌──────────────┐                                       │
│  │ 多类型系统   │ ← 决定统计时的分类口径                 │
│  │ (4种水体)    │   河流 / 湖泊 / 人工运河 / 水库        │
│  └──────┬───────┘                                       │
│         ↓                                               │
│  ┌──────────────┐                                       │
│  │ 阈值系统     │ ← 决定超警判断的可信度                 │
│  │ (2类阈值)    │   警戒水位(WRZ) / 保证水位(GRZ)        │
│  └──────────────┘                                       │
│         ↓                                               │
│  ┌────────────────────────────────┐                     │
│  │  输出结果（需标注基准+类型）    │                     │
│  │  洪泽湖 13.148m（基准：废黄河口│                     │
│  │   类型：湖泊）                 │                     │
│  └────────────────────────────────┘                     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 典型场景：用户问"洪泽湖当前水位多少？是否超警戒？"

**Step 1：查询水位**
```sql
SELECT r.tm, r.z, b.dtmnm, b.dtmel
FROM st_river_r r
JOIN st_stbprp_b b ON r.stcd = b.stcd
WHERE b.rvnm = '洪泽湖'
ORDER BY r.tm DESC LIMIT 1
```
**结果**：水位 13.148m（基准：废黄河口，高程值 NULL）

**Step 2：识别水体类型**
- rvnm = "洪泽湖"
- 查 `water_classification.md` → **湖泊**（调蓄型淡水湖）

**Step 3：验证阈值**
```sql
SELECT COUNT(*) as cnt
FROM st_rvfcch_b
WHERE STCD = '蒋坝站编码'
  AND (WRZ IS NOT NULL OR GRZ IS NOT NULL)
```
**结果**：cnt = 0 → **阈值数据全部缺失**

**Step 4：输出结果（需标注所有信息）**
```markdown
洪泽湖当前水位：**13.148m**（基准：废黄河口，高程值未记录）
- 水体类型：**湖泊**（调蓄型淡水湖）
- 代表站：蒋坝站
- ⚠️ **阈值数据缺失**：该站警戒水位（WRZ）和保证水位（GRZ）均为空，
  无法判断是否超警戒。
- 历史参考：近10年最高水位 14.25m（2020-07-21）
```

### 为什么这增加了复杂度？

| 系统 | 复杂度来源 | 影响轮次 |
|------|-----------|---------|
| **多基准** | 需查询 dtmnm/dtmel，跨站对比需换算，基准缺失处理 | +2-3 轮 |
| **多类型** | 需识别水体类型，输出时前置标注，分类争议处理 | +1-2 轮 |
| **阈值系统** | 需验证数据存在性，缺失时提供替代方案，不能硬编码 | +2-4 轮 |

**总共增加**：**+5-9 轮对话**（占水情形查询的 30-50%）

## 六、总结

### 三个系统的本质

1. **多基准系统**：解决"水位值零点参考系不一致"问题
2. **多类型系统**：解决"水体分类语义混淆"问题
3. **阈值系统**：解决"防洪指标数据严重缺失"问题

### 为什么这么复杂？

因为**真实水文世界很复杂**：
- 不同地区、不同历史时期使用不同的高程基准（多基准）
- 河流、湖泊、运河、水库的水位含义不同（多类型）
- 阈值数据严重缺失，但业务又需要（阈值系统）

### 对 LLM 的影响

每个系统都需要 LLM：
1. **记忆大量规则**（基准名称、类型映射、阈值字段）
2. **执行额外查询**（验证基准、识别类型、检查阈值）
3. **处理分支逻辑**（基准缺失怎么办、阈值缺失怎么办、类型争议怎么办）
4. **格式化输出**（标注基准、标注类型、标注阈值状态）

**结果**：LLM 需要多轮对话来处理这些复杂逻辑，直接导致耗时增加 **4倍**。
