# 9B vs 27B 评测 · 决策一页纸

> 2026-08-05 ｜ 水利 6 skill / 98 题 ｜ Gateway 真实全栈评测 ｜ [完整报告](./eval-report-9b-vs-27b-20260805.md)

## 一句话建议

**生产继续用 27B;9B 退一档但仍可用,仅适合"简单查询 + 可重试"场景,目前不建议全面替换。**

## 核心数字

| | 27B(基线) | 9B(本周) | 差距 |
|---|---|---|---|
| 平均分 | **0.864** | 0.749 | −0.115 |
| 通过率(≥0.6) | **96.9%** | 89.8% | −7.1 pp |
| 成功生成 SQL | ~98% | 91% | 偶发卡死 |

**退化不均匀** —— 简单查表几乎无损,领域推理类塌方:

|---|---|---|

## 9B 的三个风险

1. **高方差**:同题重跑波动大(Q047 四次:0.25/0.30/0.44/0.65),27B 稳定在 ~0.75。
2. **易卡死**:部分题陷入 schema 探索死循环、产 0 条 SQL;文字禁令压不住。
3. **接入敏感**:8/4 出现过整轮吐 8192 个 `?` 的灾难性回归(已修),说明 serving 配置需校验。

## 决策分叉

- **求稳 / 对外服务** → **27B**(已充分优化,96.9% 稳定)。
- **成本敏感、查询简单、可重试** → **9B 可上**,但需配重试 + 工具收敛。
- **涉及水质评价 / 预测 / 复杂融合** → **避免 9B**。

## 若选 9B,还差什么(机制层,非文字)

1. **收敛 schema 探查工具** —— 不暴露 `get_table_schema`,从根源消除死循环(最关键)。
2. **重试 / 多数投票** —— 用 2–3 次取最优,把"有机会过"变"大概率过"。
3. **轮次预算 + 强制收束** —— 超过 N 轮未出查询则套模板兜底,防回答坍缩。
4. **serving smoke 校验** —— 上线前自动检测吐 `?`/UNK。

> 前期 skill 优化(占位符根治、单轮模板、golden 对齐、超时兜底)对两模型都有效,是 9B 还能守住 89.8% 的主因。
