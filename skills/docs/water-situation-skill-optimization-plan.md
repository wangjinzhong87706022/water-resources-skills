# water-situation SKILL.md 优化方案

> **文档目的**：基于 DeerFlow Gateway 全量评测（2026-07-30）的实际表现，分析 water-situation skill 的复杂度问题，并提出具体优化方案。
>
> **评测数据**：已完成 40/98 题，平均耗时 400秒（早期），平均得分 0.909
>
> **对比基准**：rainfall skill 平均耗时 94秒，速度快 4倍

---

## 📊 问题诊断

### 核心数据对比

| 指标 | water-situation | rainfall | 差异 |
|------|----------------|----------|------|
| **文件长度** | 337 行 | 128 行 | **2.6倍** |
| **Pitfalls 警告** | 5 个（16个⚠️标记） | 2 个 | **2.5倍** |
| **Validation Gate** | 8 个子检查 | 1 个子检查 | **8倍** |
| **平均耗时** | ~400秒 | ~94秒 | **4.2倍** |
| **参考文档** | 12 个 | 6 个 | **2倍** |

### 复杂度来源

water-situation 的"高复杂度"来自三个相互独立的复杂系统：

1. **多基准系统**（3种高程基准：废黄河口/冻结吴淞/1985基准）
2. **多类型系统**（4种水体类型：天然河流/湖泊/人工运河/水库）
3. **阈值系统**（WRZ/GRZ 数据质量极差：GRZ全空，WRZ水位站基本为空）

这三个系统共增加 **5-9 轮对话**（占水情形查询的 30-50%），是导致耗时增加 4倍 的核心原因。

## 🎯 优化目标

### 主要目标
- ✅ **降低 prompt 复杂度**：337 行 → ~150 行（减少 55%）
- ✅ **减少决策点**：5 个 Pitfalls → 2-3 个
- ✅ **简化验证流程**：8 项 Validation Gate → 3-4 项
- ✅ **提升执行速度**：400秒 → 200秒（目标减少 50%）

### 次要目标
- ✅ 提升可维护性（减少重复内容）
- ✅ 降低 LLM 决策负担（减少分支逻辑）
- ✅ 保持评测质量（平均分 ≥ 0.85）

### 2️⃣ 简化 Validation Gate（交付验证）

**当前状态**：
- 8 个子检查项
- 占用 ~135 行（202-337 行）
- 包含详细的规则说明、示例、常见错误

**优化方案**：

#### 2.1 保留核心检查（3个）

**✅ 水体分类一致性检查**
- **理由**：避免语义混淆（湖泊/河流/运河混排）
- **保留内容**：
  - 分类前置标注规则
  - 快速参考表（扬州地区主要水域分类）
- **简化**：移除详细示例和常见错误

**✅ 阈值数据存在性检查**
- **理由**：避免硬编码错误（如"洪泽湖警戒水位14.35m"）
- **保留内容**：
  - 三步验证法的简化版（1步即可）
  - 缺失时的用户告知模板
- **简化**：移除详细的验证流程和替代方案

**✅ 数值合理性检查**
- **理由**：捕获明显错误（水位 -1~20m）
- **保留内容**：
  - 水位范围：-1~20m
  - 流量范围：根据业务规则
- **简化**：合并到"质量自检"步骤

#### 2.2 降级为建议（2个）

**💡 高程基准标注**
- **优化方案**：从 Validation Gate 移到 Workflow 作为可选建议

- **优先级**：低

**💡 单站代表性说明**
- **优化方案**：移到 `references/single_station_representativeness.md`
- **理由**：仅在单站统计时才需要
- **优先级**：低

#### 2.3 完全移除（3个）

**❌ 统计口径说明**
- **理由**：过于细节，LLM 按 SQL 结果输出即可

**❌ 置信度评定**
- **理由**：过于学术化，不适用于实际业务场景

**❌ S3/S5/S6 卡片化知识**
- **理由**：这些是参考文档（`schema.md`），不应在 Validation Gate 中重复

**预期效果**：Validation Gate 从 8 项减少到 3 项，减少 ~100 行

### 4️⃣ 简化 Workflow 步骤

**当前状态**：

- 占用 ~20 行（129-176 行）

**问题**：
- 部分步骤过于细节（如"水位保留两位小数"）

**优化方案**：

#### 4.1 核心步骤（保留 6 个）

**Step 1：识别查询场景**
- 河道水位 → st_river_r
- 水库水位 → st_rsvr_r
- 防洪指标 → st_rvfcch_b

**Step 2：识别测站/河道实体**
- 按名 JOIN st_stbprp_b
- 禁止占位符

**Step 3：确定时间范围**
- 实时/最新 → MAX(tm)
- 最近30天 → `tm >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)`
- 跨年对比 → 连续区间

**Step 4：判断回复深度**
- 精简/标准/详细模式

**Step 5：生成 SQL**
- JOIN st_stbprp_b
- 分区裁剪（优化建议）

**Step 6：质量自检**
- 安全规则（只读、有 WHERE、有 LIMIT）
- 数值合理性（水位 -1~20m）

#### 4.2 简化步骤（合并或移除）

**合并**：
- "前置检查：水体分类与基准一致性" → 移到 Output 阶段
- "阈值数据存在性验证" + "超警戒判断" → 合并为"阈值处理"

**移除**：
- "水位保留两位小数"（细节，可放到 references）
- "统计增强（可选）"（移到 references）
- "输出验证"（合并到质量自检）

**预期效果**：Workflow 从 12 步减少到 8 步，减少 ~40 行

**当前**：
