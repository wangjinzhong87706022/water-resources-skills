## 🔍 关键发现

### 1. **SQL 提取率偏低（72.4%）**

**原因分析**：
- 当前 SQL 提取逻辑针对 ` ```sql ... ``` ` 或 `sql = """..."""` 格式
- 但部分 LLM 响应格式不一致（多行 SQL 字符串、不同缩进等）
- **改进方案**：增强 `extract_sql()` 函数，支持更多格式

**优先级**：中（不影响总分评分，但影响 SQL 相似度评估）

### 2. **water-situation 表现最弱（0.68 分）**

**可能原因**：
- 题量最多（25 题），暴露问题更多
- L3 题复杂度高（跨年对比、水位分布等）
- **关键问题**：Q2 宝应站字段查询不完整（0.38 分）

**改进方向**：
- 检查 `water-situation/SKILL.md` 的 Workflow 是否明确"查询测站属性时联表 st_stbprp_b 获取所有字段"

### 3. **water-quality SQL 提取率最低（61.5%）**

**可能原因**：
- 水质查询常涉及多表 JOIN（sl325 水质表 + sl323 测站表）
- LLM 倾向于生成自然语言描述而非完整 SQL

**改进方向**：
- 检查 `water-quality/SKILL.md` 是否提供足够的多表 JOIN 模板

### 4. **低分用例集中于 L1/L2**

- L1 通过率 80.0%（12/15）
- L2 通过率 95.2%（20/21）
- L3 通过率 91.9%（57/62）

**分析**：
- L1 难度低但暴露基础问题（如 Q2 字段查询不完整）
- L3 复杂度高但通过率反而高（可能因为评分宽松）
